## Defects

### UAT-31-D1 — Refresh can retarget a stale Action draft to a deep-linked Action

- Role: Narin IT Staff; Ticket `TKT-20261031-000010`; Action `141e2ac5-8063-4957-bbc8-eafa7fc6661f`. The browser URL retained a hash for a different, Cancelled Action.
- Reproduce: (1) Open the Ticket through a deep link to a different Action. (2) Expand the Planned Action assigned to Kanda, open Edit and change Description to `Narin unsaved draft`. (3) In a separate authenticated Kanda session, change its Result to `Kanda saved result`. (4) Save Narin's stale draft; observe conflict. (5) Click `Refresh action`, then `Continue with draft`, set Result to Kanda's saved value, and Save.
- Expected: Refresh keeps the selected Action identity and shows its current values; continuing with the draft writes only to that Action after the user chooses to retry.
- Actual: Refresh reselects the old Action from the URL hash behind the modal. The subsequent Save targets that Cancelled Action and fails with `This action can no longer be changed.` The intended Action remains unchanged by Narin; its Result from Kanda is preserved. This reproduces after a clean reload when starting from the same deep link. The source of the retargeting is the Action list refresh effect that re-applies the URL hash on every Actions change.
- Evidence: live IAB UI observation and sanitized API status 200 for Kanda; no screenshot saved yet. No credential, cookie or token recorded.
- Retest 2026-11-01: `client/src/ActionsTaken.tsx` now applies an Action deep link only once when the Ticket's Actions first load. A two-tab Narin retest retained the intended Action through stale refresh and saved only to that ID; the earlier Cancelled Action stayed unchanged. Added a focused client regression and verified 13/13 tests plus the client build. Awaiting an exact Narin/Kanda repeat before closing UAT-31 as Pass.
